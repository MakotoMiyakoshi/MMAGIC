# Makoto Project Layout Rule

This repository follows Makoto's project-layout rule. This rule has priority over conventional repository layouts.

## Project root

The project root may contain only:

1. the `code/` directory; and
2. pipeline-output directories whose names begin with a p-number and exactly match a p-numbered MATLAB script in `code/`.

No ordinary files belong in the project root. Repository documentation, tests, helper libraries, CI examples, and metadata must live under `code/` subdirectories.

The hidden Git implementation directory `.git/`, when present in a local clone, is infrastructure metadata and is the sole technical exception.

## code/

Pipeline entry points live directly under `code/` and use p-numbered names, for example:

```text
code/
    p1200_inspect_colin27_resources.m
    p1210_build_colin27_bscr_headmodels.m
```

The p-number indicates the script's position in the processing pipeline.

Non-p-numbered reusable functions, external libraries, tests, documentation, and other support material must be placed in subdirectories under `code/`, for example:

```text
code/
    forward_model/
    legacy/
    tests/
    docs/
    ci/
```

## Pipeline-output directories

For every p-numbered pipeline script, its output directory is the project-root sibling with the exact same basename as the script:

```text
code/p1200_inspect_colin27_resources.m
p1200_inspect_colin27_resources/

code/p1210_build_colin27_bscr_headmodels.m
p1210_build_colin27_bscr_headmodels/
```

A pipeline-output directory may contain only files generated by its corresponding MATLAB script.

Do not manually add, edit, rename, or curate generated files inside a pipeline-output directory. If outputs need to change, change the generating MATLAB code and rerun the pipeline.

Pipeline scripts should rebuild their own output directory deterministically so stale or manually altered products cannot silently survive.

## Git note

Git does not track empty directories. Therefore a freshly cloned repository may contain only `code/` until a pipeline is run for the first time. Each p-numbered script creates its exact-name output directory when executed. No `.gitkeep` placeholder is used because that would violate the generated-output-only rule.
